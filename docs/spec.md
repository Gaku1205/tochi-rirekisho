# 仕様書

アプリの「何を・どう動かすか」を書く。AIは作業の前に必ずここを読む。

## 目的

福岡市の住所を入れると、古い地形図と公開データでその土地の昔と災害リスクをAIが読み解く履歴書にするサービス（元のメモ：面接で語れる、AIとデータを工夫して使った本格的なWebサービス）

## 前提

- 使う人・使う場面（デザイン担当の分析。推定を含む）：
  - 福岡市で部屋や家を探している人が、候補の住所を入れて「昔は田んぼか池か、浸水や地盤はどうか」を内見の前に確かめる
  - 地元の歴史が好きな人が、自分の住む町の1926年・1948年・1975年といまを、境目をずらして見比べる
  - 調べた結果を縦長の1枚の画像にして、家族や部屋探しの相手にスマホで送る
  - 登録なしで誰でも使う。調べられるのは福岡市の7区だけ
- 技術：Next.js（App Router）＋TypeScript、テストはVitest

## 画面

（ページごとに、何を出して何ができるか）

### 結果の画面の地図で地点を選ぶ（`/tochi/[町]`、`/#record`）

- 選べる地図は、結果の画面の境目の地図だけ（トップの最初の1画面の地図では選べない）。地図の下に注「地図を押すと、その地点を調べられます（スマホは長押し）」を出す
- 選び方：マウスは地図をクリック。タッチは同じ場所を 0.5 秒押したまま（長押し）。キーボードは地図に焦点があるとき Enter で、地図の中心の地点
- 次の操作は地点を選ばない：ドラッグ・ピンチ（指が2本）・ダブルクリックの拡大・境目のつまみ・＋−ボタン・札やリンクの上の操作。押してから 8px より動いたら、クリックでも長押しでもない。ダブルクリックは、1回目のクリックを 0.26 秒待ってから選ぶので、2回目が来たら選ばない
- 選んだ地点（`geo.ts` の `unproject` で画面の位置→緯度経度）に印を出し、その近くに札を出す。札が出ているときに地図を押す（短い押し）と札が閉じる。Esc でも閉じる
- 地点は `searchPoint`（`src/lib/search.ts`）で、記録のある12の町のうちいちばん近い町に結びつける。距離は `distanceMeters`。1,500m 以内なら「見つかった」、超えたら「範囲の外」
  - 見つかった：札に町名（「大橋2丁目」）と「この地点の履歴書を見る」（`/tochi/[slug]` へ）
  - 範囲の外：札に「ここは調べられる町から遠すぎます」だけを出す。近い町への案内・リンクは出さない
- 記録は町ごとの値なので、選んだ地点そのものの数値ではなく、いちばん近い町の記録を見ることになる（地点ごとの記録は別の仕事）

### AIの要約

- `GET /api/summary?slug=ohashi-2` が `{ summary, source }` を返す。`source` は `"llm"`（LLMが作った）か `"fallback"`（人が書いた `place.summary`）
- 町の記録（年代ごとの土地の様子・浸水・地盤・地価）を「事実の表」（テキスト）にして、LLM（Gemini の無料枠）に渡す。渡すのはこの表だけ
- 指示は「表に書かれていない事実・数字・固有名詞を足さない」「最初の1文で結論（その土地の昔と災害リスクのひとこと）、続けて根拠を1文」「全部で2文・120字ほど」「危なさを煽らず、淡々と」「日本語」
- 返事は確かめる。空・2文を超える・長すぎる・表に無い数字（半角・全角）を含むときは使わない
- キーが無い・タイムアウト（8秒）・エラー・確認で不合格のときは、200 で `place.summary` と `source: "fallback"` を返す。知らない slug は 404
- 同じ slug のLLMの結果はプロセス内に覚える（再起動で消えてよい）
- キーは環境変数 `GEMINI_API_KEY`、モデル名は `GEMINI_MODEL`（無ければ軽い無料枠のモデル）
- 画面からの呼び出しは、この節では決めない（別の作業）
