# 仕様書

アプリの「何を・どう動かすか」を書く。AIは作業の前に必ずここを読む。

## 目的

福岡市の住所を入れると、古い地形図と公開データでその土地の昔と災害リスクをAIが読み解く履歴書にするサービス（元のメモ：面接で語れる、AIとデータを工夫して使った本格的なWebサービス）

## 前提

- 使う人・使う場面（デザイン担当の分析。推定を含む）：
  - 福岡市で部屋や家を探している人が、候補の住所を入れて「昔は田んぼか池か、浸水や地盤はどうか」を内見の前に確かめる
  - 地元の歴史が好きな人が、自分の住む町の1926年・1948年・1975年といまを、境目をずらして見比べる
  - 調べた結果を縦長の1枚の画像にして、家族や部屋探しの相手にスマホで送る
  - 登録なしで誰でも使う。調べられるのは福岡市の7区だけ
- 技術：Next.js（App Router）＋TypeScript、テストはVitest

## 画面

（ページごとに、何を出して何ができるか）

### 結果の画面の地図で地点を選ぶ（`/tochi/[町]`、`/#record`）

- 選べる地図は、結果の画面の境目の地図だけ（トップの最初の1画面の地図では選べない）。地図の下に注「地図を押すと、その地点を調べられます（スマホは長押し）」を出す
- 選び方：マウスは地図をクリック。タッチは同じ場所を 0.5 秒押したまま（長押し）。キーボードは地図に焦点があるとき Enter で、地図の中心の地点
- 次の操作は地点を選ばない：ドラッグ・ピンチ（指が2本）・ダブルクリックの拡大・境目のつまみ・＋−ボタン・札やリンクの上の操作。押してから 8px より動いたら、クリックでも長押しでもない。ダブルクリックは、1回目のクリックを 0.26 秒待ってから選ぶので、2回目が来たら選ばない
- 選んだ地点（`geo.ts` の `unproject` で画面の位置→緯度経度）に印を出し、その近くに札を出す。札が出ているときに地図を押す（短い押し）と札が閉じる。Esc でも閉じる
- 地点は `searchPoint`（`src/lib/search.ts`）で、記録のある12の町のうちいちばん近い町に結びつける。距離は `distanceMeters`。1,500m 以内なら「見つかった」、超えたら「範囲の外」
  - 見つかった：札に町名（「大橋2丁目」）と「この地点の履歴書を見る」（`/tochi/[slug]` へ）
  - 範囲の外：札に「ここは調べられる町から遠すぎます」だけを出す。近い町への案内・リンクは出さない
- 記録は町ごとの値なので、選んだ地点そのものの数値ではなく、いちばん近い町の記録を見ることになる（地点ごとの記録は別の仕事）

### 見つからない・範囲の外（`/search`）

- 住所が見つからない・福岡市の外・未入力のどれでも、カードの中の「いま調べられる町：12」の下に、記録のある12の町すべてを町名＋丁目（例：大橋2丁目）のリンクの一覧として出す。並びは `PLACES` の順。押すとその町の履歴書 `/tochi/[町]` に行く
- 一覧は画面の幅に関わらずカードの中に出す（スマホで地図の札まで行かなくても選べる）。地図の上の札は今までどおり残す
- 文言は、地図の札ではなくカードの中の一覧を指す（「下の町から選んでください」）。福岡市外の文言にも、下の一覧から選べることを1文足す

### AIの要約

- `GET /api/summary?slug=ohashi-2` が `{ summary, source }` を返す。`source` は `"llm"`（LLMが作った）か `"fallback"`（人が書いた `place.summary`）
- 町の記録（年代ごとの土地の様子・浸水・地盤・地価）を「事実の表」（テキスト）にして、LLM（Gemini の無料枠）に渡す。渡すのはこの表だけ
- 指示は「表に書かれていない事実・数字・固有名詞を足さない」「最初の1文で結論（その土地の昔と災害リスクのひとこと）、続けて根拠を1文」「全部で2文・120字ほど」「危なさを煽らず、淡々と」「日本語」
- 返事は確かめる。空・2文を超える・長すぎる・表に無い数字（半角・全角）を含むときは使わない
- キーが無い・タイムアウト（8秒）・エラー・確認で不合格のときは、200 で `place.summary` と `source: "fallback"` を返す。知らない slug は 404
- 同じ slug のLLMの結果はプロセス内に覚える（再起動で消えてよい）
- キーは環境変数 `GEMINI_API_KEY`、モデル名は `GEMINI_MODEL`（無ければ軽い無料枠のモデル）
- 画面からの呼び出しは、この節では決めない（別の作業）
- 画面に出る要約（`place.summary`・手で書いた文）は、年代ごとの地図から読み取れる昔の土地の様子（田んぼ・畑・砂丘・台地など）だけを書く。浸水・地盤・地価の良し悪しは言い切らない。「水に浸かりにくい」「浸水の心配が少ない」「高い土地」「安全」のような災害リスクの言い切りは、データが入っていても要約に書かない（危なさは、下の記録の行で数字・言葉として出す）
- 要約の下の注は「年代ごとの地図から読み取った、昔の土地の様子の要約」（画面とシェア画像で同じ文言。`docs/design.md` の「AIの要約」）。AIが作った文ではないので「AIが読み解いた」とは書かない

### 町の記録の出どころ（浸水）

- 浸水の想定（`Place.flood`）は、国土数値情報の洪水浸水想定区域から、12の町の地点（`Place.at` の1点）の最大規模の想定の深さを調べ、あらかじめ `src/data/flood.json` に入れる。実行時に外のAPIへは取りにいかない
- JSON：`source`（データ名・版・取得日）と、町ごとの `slug`・`depth`・`river`。`depth` は区分（`0.5m未満`・`0.5〜1.0m`・`0.5〜3.0m`・`1.0〜3.0m`・`3.0〜5.0m`・`5.0m以上`）、区域の外は `なし`、確かめられなかった町は `null`。`river` は河川名（不明は `null`）。推測や記憶で埋めない。出どころで確かめた値だけを入れる
- `features.flood`（0〜1、3m で 1）はこの区分から作る（`src/lib/flood.ts` の `floodFeature`）。`null` の町は `features.flood` も `null`
- `null` の町は画面・シェア画像・AIの事実の表で「データなし」と控えめに出す。似た土地（`similar.ts`）は、どちらかが `null` の特徴を飛ばし、残りの特徴だけで比べる（共通点の言葉にも浸水を足さない）
- 浸水の出どころは、結果の画面の下の注と「このサービスについて」に書く。地盤・地価の出どころは次の節
- いまの `flood.json` は、公開データを取得できない環境で作ったため、全町 `null`。取得できた町から入れていく

### 町の記録の出どころ（地盤・地価）

- 地盤（`Place.ground`）は国土地理院の土地条件図、地価（`Place.price`）は国土交通省の地価公示から、12の町の地点（`Place.at`）で調べ、あらかじめ `src/data/ground.json`・`src/data/price.json` に入れる。実行時に外のAPIへは取りにいかない
- JSON は `flood.json` と同じ形：`source`（データ名・版・取得日・`memo`）と、町ごとの `slug` を持つ `places`
  - 地盤：`value`（土地条件図の地形分類の名前をそのまま。例：谷底平野・氾濫原、砂州・砂丘、台地・段丘）と `note`（出どころを短く）
  - 地価：`manYen`（1㎡あたり万円）・`change10y`（10年の変化の%）・`note`（公示地点の名前や年）
- 推測や記憶で埋めない。確かめられない町は、値を `null`（`value` か `manYen` のどちらかが `null` なら、その欄は「データなし」）。`change10y` だけ `null` のときは、地価の数字は出して、変化の文は省く
- `features.lowland`（低い土地か）は、地盤が取れた町は分類から作る（`src/lib/ground.ts` の `lowlandFeature`：低地・埋立地など 1、台地・段丘 0.4、山地・丘陵 0）。`null` の町や知らない分類は、`places.ts` の手書きの値をそのまま使う。`similar.ts` の比べ方は変えない
- `null` の町は画面・シェア画像・AIの事実の表で「データなし」と控えめに出す（0円・空欄・NaN にしない）
- 出どころは、結果の画面の下の注と「このサービスについて」に書く
- いまの `ground.json`・`price.json` は、公開データを取得できない環境で作ったため、全町 `null`。取得できた町から入れていく
